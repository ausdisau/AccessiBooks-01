Perfect. With **Vite + Tailwind** you’ll typically run:

* **`apps/web`** = Vite/Tailwind client (Shaka Player, UI, auth calls)
* **`services/drm`** = standalone Node/TypeScript microservice (tokens, entitlements, Widevine license endpoint)
* Optional **`packages/shared`** = shared types (JWT claims, API DTOs)

Here’s a **Replit-friendly monorepo folder structure** that stays tidy even as the DRM bits get… spicy 🔥🔑

# 🔌 How the pieces talk to each other

### `apps/web` (Vite) calls

* `POST services/drm/api/playback/token` → gets `{ token, manifestUrl, licenseUrl }`

### Vite Shaka Player config

* License requests go to:

  * `POST /drm/widevine/license`
* Token is attached as `Authorization: Bearer <token>` using a request filter.

# ⚙️ Replit run setup (simple and practical)

## Option A: one Replit, run both

Root `package.json` scripts:

```json
{
  "scripts": {
    "dev": "concurrently \"pnpm -C services/drm dev\" \"pnpm -C apps/web dev\"",
    "build": "pnpm -C services/drm build && pnpm -C apps/web build"
  }
}
```

Then `.replit` runs `pnpm dev`.

## Option B: one Replit for web, one for DRM

Cleaner for prod, but Option A is totally fine for early stage.

# 🧠 Small design choice that will save you later

Keep **DRM and tokens** in the DRM microservice, not in the Vite app.
The web app should only ever see:

* manifest URL
* license URL
* short-lived playback token

Not:

* keys
* KIDs
* DRM internals
