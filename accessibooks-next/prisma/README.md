# Prisma (AccessiBooks Next.js)

Source-of-truth schema for the rebuilt Next.js AccessiBooks app. Ported from the
legacy Drizzle schema at `lib/db/src/schema/schema.ts`. snake_case Postgres
table/column names are preserved via `@map` / `@@map` so the data shape stays
compatible with the legacy database.

## Layout

- `schema.prisma` — full Prisma data model (~100 models, no battle-pass tables).
- `seed.ts` — seeds the `plans` table (free / plus / premium / institutional)
  with the same pricing constants the legacy `subscriptionService.ts` uses.
- `migrations/` — generated by `prisma migrate dev`.

## Setup

Set `DATABASE_URL` in `.env.local` (or shell), then:

```bash
# Generate the Prisma client (writes to node_modules/@prisma/client):
pnpm prisma generate

# Apply migrations + create one if the schema drifted:
pnpm prisma migrate dev --name init

# Seed plans:
pnpm prisma db seed
```

## Useful commands

| Command | What it does |
| --- | --- |
| `pnpm prisma migrate dev` | Apply pending migrations, prompt to create a new one if the schema changed. |
| `pnpm prisma migrate deploy` | Apply pending migrations non-interactively (CI / prod). |
| `pnpm prisma migrate reset` | Drop DB, re-run migrations, re-run seed. |
| `pnpm prisma studio` | Browse data in a local web UI. |
| `pnpm prisma format` | Auto-format `schema.prisma`. |

## Notes / intentional deviations from the legacy Drizzle schema

- **Battle pass tables excluded.** `battle_passes`, `battle_pass_milestones`,
  `battle_pass_purchases` are intentionally omitted. No other model in the
  ported schema currently has an FK into those tables, so no `// TODO: source
  enum without battle_pass` markers were needed.
- **`TIER_FEATURES` `Infinity` → `-1`.** The legacy TypeScript constants store
  unlimited quotas as `Infinity`, which is not JSON-serialisable. The seed
  encodes them as `-1` inside the JSONB `features` blob; the API layer should
  treat `-1` as "unlimited".
- **Singleton client.** Import the shared client from `@/lib/db`. It uses the
  Next.js dev-global pattern so hot-module reloads don't leak Prisma clients.
